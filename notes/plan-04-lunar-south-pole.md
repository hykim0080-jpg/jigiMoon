# ④ Lunar Landing Site Navigator: 작업 계획 (2026-11-14 15:40 KST)

## 한 문장 문제
"달 남극 착륙이 며칠 밀리거나 몇 km 옮겨지면, 그곳의 전기(햇빛)와 지구 직접 통신은 어떻게 바뀌나?"를 몇 초 만에 비교해 주는 도구.

원문이 가장 강조하는 것: 기존 도구(QuickMap, Moon Trek, JPL Horizons)는 전문가용이라 "장소×날짜" 조합 비교가 느림 → 쉬운 빠른 비교.

## 결과물 (기능 우선순위)
1. **하늘 돔 보기 (필수):** 착륙지 하나를 고르면 360° 지평선 실루엣(지형) 위에 해와 지구의 궤적을 그림. 지금 해가 지기까지 / 지구가 지기까지 남은 시간 표시
2. **일정 지연 달력 (차별점):** 가로 = 날짜(몇 달), 세로 = 후보지 여러 곳. 칸마다 "햇빛 O/X, 통신 O/X, 둘 다 O" 색칠 → 날짜가 밀리면 어디로 옮기면 되는지 한눈에
3. **나란히 비교:** 2~3곳 선택 → 햇빛 %, 가장 긴 어둠 기간, 지구 보이는 %, 둘 다 되는 시간대
4. **"왜?" 설명:** 해가 가려지는 순간, 어느 방향의 어느 산이 가리는지 실루엣에 강조. "몇 km 차이로 결과가 뒤집히는 이유"를 보여줌 (원문 고려 사항)
5. (여유 있으면) 교육 모드: "서울 아파트 일조권 분석과 같은 원리" 비유, 지구와 다른 점(대기 없음, 해가 옆으로 돎)

## 데이터 (모두 NASA 공개, 출처 명시)
- **지형:** PGDA LOLA 남극 착륙지 DEM 5 m/px (pgda.gsfc.nasa.gov/products/78, data/LOLA_5mpp) + 먼 지평선용 넓은 DEM (20 m 또는 large-scale, products/92)
- **검증용 조도:** PGDA Lunar Polar Illumination (products/69): 미리 계산된 평균 조도 % → 우리 계산과 비교 (Validity 점수)
- **천체 위치:** NAIF SPICE 커널(DE440, 달 자세 moon_pa, 프레임) + Python spiceypy. 또는 JPL Horizons API(달 표면 지점 관측자 지원). 칭동은 천체력에 자동 포함
- **후보지 목록:** Artemis III 후보 지역 9곳, IM-2 착륙지(Mons Mouton), 샤클턴 분화구 가장자리, 찬드라얀-3 등 (좌표 출처 확인 필요)

## 계산 방법
1. **지평선 곡선(horizon mask):** 착륙지에서 방위 0~360°(0.5° 간격)로 DEM을 따라 최대 수백 km까지 광선 추적. 각 지점 고도각 = atan((h − h0 − d²/2R) / d), R = 1737.4 km (곡률 보정). 방향별 최댓값 = 지평선 높이
2. **해·지구 방위·고도:** 2026~2030년, 1시간 간격. 해는 원반 크기(약 0.53°)를 고려해 "보이는 비율" 계산
3. **지표:** 햇빛 % / 가장 긴 연속 어둠 / 태양 고도각 / 지구 보이는 % / 둘 다 되는 시간대 / 다음 일몰·지구몰까지 남은 시간
4. 후보지는 미리 계산(JSON). 임의 좌표는 서버(Python)에서 즉석 계산(수 초 목표)

## 역할 분담
- **팀원 (분석):** DEM 받기 → 지평선 곡선 → SPICE 궤적 → 지표 계산 → JSON 출력. PGDA 조도 %와 검증
- **현기 (웹):** 하늘 돔(극좌표 차트), 일정 지연 달력(히트맵), 비교 화면, 남극 지도(극 투영). React + D3/Plotly 정도. 가짜 JSON으로 먼저 화면 만들고 나중에 실제 데이터 연결
